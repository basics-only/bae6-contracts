# bae6-ai — AI Gateway and Extension Implementation Plan

## Intent and dependency rule
`core` is a lightweight inference/metering gateway. Agents, evals, guardrails and framework integrations are **optional** packages. Core must never import agents or LangChain. Use one repo with package-specific builds, versions and owners.

## Layout
```
packages/core/              # model interfaces, provider adapters and client
packages/agents/            # native tool loop, workflow, optional checkpoints
packages/evals/             # datasets, scorers, comparative reporting
packages/guardrails/        # deterministic policy gates and content hooks
packages/integrations/langchain/  # optional adapter only
services/gateway/           # hosted core HTTP API
services/agent-worker/      # optional background execution
services/eval-worker/       # optional evaluations
sdk/typescript/; sdk/python/
```

## Core inference gateway
Supported cloud providers: **AWS Bedrock and GCP Vertex AI only**. Define `ModelProvider` with `capabilities`, `generate`, `stream`, `embed` where supported. Include model/region routing, provider- and model-specific modality capability matrix (text, images, audio, tools, structured output, embeddings) and explicit unsupported-operation errors.

### HTTP API (versioned documented subset)
- `POST /v1/chat/completions`; `POST /v1/responses` documented OpenAI-style subset.
- `POST /v1/embeddings`; `POST /v1/decisions` (bae6 native validated structured classification); `POST /v1/generations` (bae6 native multimodal).
- `GET /v1/models`, `GET /v1/usage`, `GET /v1/budgets`; restricted admin endpoints.
- Streaming via SSE, bounded backpressure and cancellation; no unbounded response buffering.

### Metering/budgets
- Verify identity from token, map org/app/user server-side. Produce immutable request/usage ledger events and projections by tenant/app/user/provider/model/modality.
- Atomic preflight budget reservations in shared Postgres; finalize with measured provider usage; refund unused reservation; lease/expiry and reconciliation after pod crash.
- Idempotency key and durable request ID; retry only when safe to avoid double spend/model calls. Record uncertain provider outcomes explicitly.
- Versioned price books; decimal arithmetic; measured vs estimated cost; cloud bill reconciliation; never assume missing usage == zero.
- Distributed org/user token/RPS/concurrency limits. Bound provider retries with circuit-breaking/backoff and regional policies; preserve tenant controls on fallback.

## Agents module
Native small Agent/Tool/Runner interfaces; schema-validated tool inputs, step/time/cost ceilings, tool allowlists, human approval hook, cancellation and auditable tool receipts. Checkpointing and worker execution optional; no dependency on LangChain. Integrate MCP tools via separate context adapter, not required in core. Treat retrieved text as untrusted instructions.

## Evaluations module
Small reproducible test datasets and scorers: exact match, schema validity, task success, latency/cost, model-based grader optional; dataset/version provenance, run IDs, controlled seeds where meaningful, baseline comparison and regressions. Eval worker optional.

## Guardrails module
Deterministic pre/post tool policy, secret/PII handling hooks, input/output size bounds, schema validation, per-tool permissions and budgets. AI safety classifiers optional, not security controls.

## Integration modules
Opt-in adapters for LangChain and external tool providers; core API stays framework-agnostic. Explicitly track transitive dependencies.

## Build phases
1. Define `ModelClient`, `ModelProvider`, `UsageEvent`, streaming format and capability schemas.
2. Bedrock Converse/stream support + Vertex generation/stream support; provider compatibility fixtures.
3. HTTP gateway, auth and both SDKs; streaming and cancellation.
4. Metering ledger, pricebook, atomic reservations, budgets and rate limits.
5. Agent native runner and tool validation, then eval module, then deterministic guardrails.
6. Optional workers and LangChain integration after native path is stable.

## Acceptance criteria
- Bedrock and Vertex smoke tests and offline mocked fixture tests, including unsupported modality cases.
- Three replicas under concurrent budget spend never exceed specified reserved budget semantics; duplicate event finalization impossible; crash recovery reconciles reservations.
- Client identity spoofing rejected; budgets and routing scoped per tenant.
- Streaming cancellation does not retain unbounded buffers or leave orphaned usage reservations.
- `@bae6/ai-core` installs without agent frameworks; TS/Python SDK contract parity; core is independently deployed and upgraded.
